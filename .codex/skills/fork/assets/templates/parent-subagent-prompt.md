# Шаблон prompt для подагента одной карточки

Мы начали миграцию Codex на новую upstream-версию `rust-v{{version}}` в текущей
рабочей копии. Тебе нужно проверить и при необходимости доработать ровно одну
fork-карточку.

Контекст:

- Рабочая директория: `{{repo_root}}`.
- Текущая ветка: `{{branch}}`.
- Выбранная карточка: `{{card}}`.
- Слияние upstream уже выполнено, но общий коммит слияния еще не сделан.
- В рабочем дереве могут оставаться неразрешенные конфликты Git.
- Родительский агент потом сам проверит diff, запустит сборку, тесты,
  форматирование, генераторы, markdownlint и обновит общую таблицу миграции.

Задача:

1. Прочитай правила для этого запуска:
   `.codex/skills/fork/references/subagent-one-card.md`.
2. Прочитай выбранную карточку:
   `{{card}}`.
3. Проверь в текущей кодовой базе, полностью ли перенесена именно эта карточка
   после слияния `rust-v{{version}}`.
4. Если нужно, внеси минимальные правки только по этой карточке.
5. Если в рабочем дереве есть конфликтные маркеры Git, разрешай только те
   участки, которые явно относятся к выбранной карточке.
6. Если меняешь код, схемы, конфигурацию, тесты или контракт выбранной
   fork-доработки, обнови выбранную владеющую карточку:
   `{{card}}`
   в том же изменении.
7. Остальные карточки не трогай: ими будут заниматься другие агенты.

Жесткие ограничения:

- Не читай parent-only references вроде
  `.codex/skills/fork/references/parent-migration.md`.
- Не читай другие `docs/fork/*.md` целиком.
- Не читай и не редактируй `docs/fork/migration-{{version}}.md`: таблицу
  миграции обновляет родительский агент.
- Не запускай сборку, тесты, генераторы, `fmt`, `fix`, markdownlint или другие
  проверки: этим занимается родительский агент.
- Не делай `git add`, `git stash`, `git commit`, `git push` и другие
  git-операции.
- Не восстанавливай старый fork-diff механически; сверяй контракт карточки с
  текущим кодом.
- Не читай другие карточки, чтобы определить владельца чужого конфликта. Если
  конфликт не относится явно к выбранной карточке, оставь его без изменения и
  укажи в отчете.
- Учитывай, что в рабочем дереве уже есть слияние upstream и изменения от
  других подагентов; не откатывай чужие изменения.

Финальный отчет сделай коротким по формату из
`.codex/skills/fork/references/subagent-one-card.md`.
