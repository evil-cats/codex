# Инструкция для подагента: одна fork-карточка

Статус: `перенесено`.

Ты подагент, которому родительский агент поручил проверить и при необходимости
доработать миграцию ровно одной fork-карточки в текущей кодовой базе.

Рабочая копия уже находится после слияния нового upstream-релиза. В ней могут
оставаться неразрешенные конфликты Git. Ты не выполняешь общий апгрейд fork, не
строишь план всей миграции и не выбираешь следующую карточку.

Не читай parent-only references вроде `references/parent-migration.md`. Все
правила, нужные тебе для этого запуска, находятся в этом файле и в выбранной
карточке.

## Главное правило

Один запуск = одна выбранная карточка `docs/fork/<card>.md`.

Работай только с выбранной карточкой и файлами текущей кодовой базы, которые
прямо нужны для проверки или доработки этой карточки. Другие fork-карточки
обрабатывают другие агенты.

Если меняешь код, схемы, конфигурацию, тесты или другой контракт выбранной
fork-доработки, обнови выбранную карточку `docs/fork/<card>.md` в том же
изменении. Карточка должна оставаться источником handoff для этой доработки.

## Конфликты слияния

Незавершенное слияние является допустимым входным состоянием для подагента.
Родительский агент не обязан заранее очищать все конфликтные маркеры.

При необходимости посмотри текущий список конфликтующих файлов:

```bash
git diff --name-only --diff-filter=U
```

Разрешай только те конфликтные участки, которые нужны для переноса контракта
выбранной карточки. Не читай другие `docs/fork/*.md` целиком, чтобы определить
владельца чужого конфликта. Если конфликт мешает работе, но не относится явно к
выбранной карточке, оставь его без изменения и укажи это в отчете
родительскому агенту.

### Добавление новых файлов и путей с разрешёнными конфликтами в index

Используй `git add -- <path>` только для явно указанного пути в двух случаях:

- ты создал новый task-owned файл в границах выбранной карточки;
- ты полностью разрешил относящийся к выбранной карточке конфликт слияния в
  этом пути.

Перед `git add` проверь конкретный путь через `git status --short -- <path>`.
Конфликтующий путь можно добавлять в index, только если все конфликтные участки
этого файла относятся к выбранной карточке и полностью разрешены. Если в том же
файле остаётся чужой или неясный конфликт, не добавляй файл в index и сообщи
родительскому агенту блокирующее условие.

Перед добавлением разрешённого конфликта проверь путь через
`git diff --check -- <path>`. После `git add` повторно выполни:

```bash
git status --short -- <path>
git diff --name-only --diff-filter=U -- <path>
```

Последняя команда не должна показывать путь как неразрешённый. Если выбранное
решение удаляет конфликтующий файл, явный `git add -- <deleted-path>` фиксирует
это удаление в index.

Не используй `git add .`, `git add -A`, `git add -u`, каталоги, glob-шаблоны или
другой широкий pathspec. Не добавляй обычные изменения существующих файлов,
чужие изменения, файлы другой карточки или JSON-карту миграции. Добавление в
index не означает, что родительский агент уже проверил или одобрил результат.

## Что читать

Читай только:

- этот файл;
- выбранную карточку `docs/fork/<card>.md`;
- файлы кода, тестов, схем, конфигурации и документации, которые прямо нужны
  для проверки или доработки выбранной карточки;
- сведения git и diff только в границах выбранной карточки.

## Что запрещено

Нельзя:

- читать parent-only references вроде `references/parent-migration.md`;
- читать другие `docs/fork/*.md` целиком;
- читать или менять `docs/fork/migration/*.json`;
- переносить больше одной карточки;
- выбирать следующую карточку;
- восстанавливать старый diff целиком;
- менять несвязанные файлы;
- разрешать конфликтные маркеры Git вне области выбранной карточки;
- выполнять `git commit`, `git push`, `git stash`, `git reset`, переключать
  ветки или менять общую Git-историю;
- запускать сборку, тесты, генераторы, форматирование, `fix` или другие проверки
  уровня проекта; узкие Git-проверки конкретного пути из раздела выше являются
  разрешённым исключением;
- расширять область работы без возврата к родительскому агенту.

Если для продолжения нужна другая fork-карточка, широкий diff или решение по
общей миграции, остановись и верни блокирующее условие.

## Рабочий порядок

1. Прочитай этот файл.
2. Прочитай выбранную fork-карточку полностью.
3. Определи, какие owner-файлы, контракты, тесты и проверки она описывает.
4. Проверь по текущей кодовой базе, присутствует ли доработка после слияния.
5. Если доработка отсутствует или неполна, внеси минимальные изменения только
   в границах выбранной карточки.
6. Если внес изменения или уточнил контракт выбранной доработки, обнови
   выбранную карточку `docs/fork/<card>.md`.
7. Новые task-owned файлы и пути с полностью разрешёнными конфликтами выбранной
   карточки добавь в index только явной командой `git add -- <path>` и выполни
   проверки конкретного пути из раздела выше.
8. Если доработка больше не применима, явно объясни почему.
9. Если нужны другая карточка, широкий diff, сборка, тесты, генераторы,
   форматирование или `fix`, не запускай их сам: верни родительскому агенту
   блокирующее условие или список нужных проверок.
10. Верни короткий отчет родительскому агенту.

## Формат отчета

Отчет должен быть коротким. Не превращай его в audit log и не дублируй
содержимое выбранной карточки. Цель отчета - дать родительскому агенту
достаточно информации, чтобы проверить diff, установить машинный статус
выбранной записи через `fork migration set-card-status` и
включить нужные проверки в общий проверочный проход после обработки карточек.

Жесткий лимит:

- не больше 12 коротких пунктов;
- без длинных списков доказательств по строкам кода;
- без подробного пересказа прочитанных файлов;
- для прочитанных и измененных файлов указывай только пути;
- подробности давай только для реальной доработки, блокера или риска, который
  должен проверить родительский агент.

Верни отчет в таком виде:

- Карточка:
- Рекомендуемый итоговый статус (`migrated`, `notApplicable`, `reverted`,
  `blocked` или `needsFix`):
- Прочитанные файлы:
- Измененные файлы (пометь новые файлы и пути с разрешёнными конфликтами,
  добавленные в index):
- Что проверено:
- Что доработано:
- Как обновлена выбранная карточка:
- Какие проверки нужны для общего проверочного прохода:
- Какие блокирующие условия остались:
- Подтверждение: parent-only references целиком не читались.
- Подтверждение: другие `docs/fork/*.md` целиком не читались.
- Что должен проверить родительский агент:
