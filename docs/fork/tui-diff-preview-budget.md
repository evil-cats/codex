# Настраиваемый бюджет предпросмотра diff на каждый файл

## Обзор

Эта карточка владеет fork-доработкой Hermione, которая ограничивает встроенный
TUI-предпросмотр diff независимым бюджетом на каждый изменённый файл. Настройка
`tui.diff_preview_max_rows_per_file` задаёт число отрисованных строк содержимого
одного файла; при отсутствии настройки используется значение `300`.

Полный diff в `transcript` и raw-представлении не ограничивается этим бюджетом.
Доработка меняет только основную ячейку истории `PatchHistoryCell`.

## Зачем это нужно

Upstream Codex 0.153.0 удалил прежний общий лимит в двенадцать строк вместе с
отдельным путём `create_diff_preview()`: `PatchHistoryCell::display_lines()` и
`PatchHistoryCell::transcript_lines()` используют один полный
`create_diff_summary()`. Основная ячейка истории из-за этого показывает весь diff
без ограничения, а различие между компактным предпросмотром и полным
`transcript` исчезает.

Hermione намеренно не принимает ни прежний общий бюджет, при котором первый
большой файл лишал следующие файлы содержимого, ни новый неограниченный основной
рендер. Она ограничивает каждый файл отдельно, делает размер явной
пользовательской настройкой и сохраняет полный diff только для `transcript` и
raw-представления.

`PatchHistoryCell`, поэтому два независимых TUI-контракта не объединяются.

## Итоговый контракт

- Ключ `tui.diff_preview_max_rows_per_file` принимает положительное целое
  число. Значение `0` отклоняется при загрузке конфигурации.
- Если ключ отсутствует, эффективный бюджет равен `300` отрисованным строкам
  содержимого на каждый изменённый файл.
- Каждый файл получает полный собственный бюджет. Неиспользованный остаток одного
  файла не переносится к другому, а сокращение одного файла не лишает содержимого
  следующие файлы.
- Бюджет измеряется после учёта ширины терминала и переноса. Одна длинная строка
  исходника может занять несколько строк бюджета; разделитель хунков `⋮` также
  входит в бюджет файла.
- Общий заголовок, заголовки файлов, пустые разделители между файлами и итоговый
  маркер `Diff preview limited` не входят в бюджет содержимого.
- Если содержимое хотя бы одного файла не помещается, TUI сохраняет единственный
  итоговый маркер `Diff preview limited (ctrl + t to view transcript).`.
- Лексикографический порядок файлов, статистика добавленных и удалённых строк,
  подсветка diff и существующие правила отображения хунков не меняются.
- Защитный предел предварительного сканирования `64 KiB` сохраняется: он не даёт
  символам нулевой ширины или минифицированному содержимому обойти ограничение до
  построения перенесённых строк и фрагментов подсветки.
- `transcript_lines()` и raw-представление продолжают строить полный diff без
  ограничения на каждый файл. Настройка влияет только на основной встроенный
  предпросмотр.

## Архитектурное решение

Сырой TUI-конфиг хранит необязательное положительное значение
`diff_preview_max_rows_per_file`. Слой конфигурации преобразует его в эффективный
`usize`, подставляя общее значение по умолчанию `300`. Благодаря положительному
типу значение `0` отклоняется десериализатором, а не получает неявный смысл
«ничего не показывать» или «отключить лимит».

`PatchHistoryCell` сохраняет эффективный бюджет в момент создания. Оба
рабочих пути создания ячейки — активная обработка apply-patch и предпросмотр
изменений неактивного потока — получают одно значение из загруженного `Config`.
Текущее значение не читается через глобальное состояние во время каждого
рендера.

`create_diff_preview()` передаёт бюджет в общий рендерер, который заново создаёт
счётчик для каждого файла. Результат сокращения накапливается отдельно от
локального остатка строк, поэтому пропуск хвоста первого файла не обнуляет бюджет
следующего. `create_diff_summary()` продолжает передавать неограниченное значение
для transcript и raw-представления.

Значение по умолчанию принадлежит конфигурационному контракту, а не
`diff_render`: это не позволяет TOML, эффективной конфигурации и TUI расходиться
при дальнейшем переносе. Существующее ограничение сканирования остаётся в модуле
`preview` как независимая защита от патологического входа.

## Порядок повторения при переносе

1. Найти текущий upstream-рендерер `PatchHistoryCell` и проверить, не объединены
   ли основной предпросмотр и полный `transcript` в один неограниченный путь. Если
   объединены, восстановить отдельный `create_diff_preview()` только для
   `display_lines()`.
2. Проверить актуальные типы TUI-конфигурации и эффективный `Config`. Если upstream
   уже добавил эквивалентную положительную настройку на каждый файл, сопоставить
   значение по умолчанию, схему и оба рабочих пути создания ячейки до удаления
   fork-слоя.
3. Перенести ключ `tui.diff_preview_max_rows_per_file` со значением по умолчанию
   `300` и обновить сгенерированную схему конфигурации штатной проверкой
   генераторов.
4. Передать эффективное значение в `PatchHistoryCell` активного и неактивного
   потоков, не добавляя глобальное изменяемое состояние рендерера.
5. В рендерере сбрасывать счётчик строк перед содержимым каждого файла и отдельно
   накапливать общий признак сокращения для итогового маркера.
6. Сохранить неограниченный путь transcript/raw и защитный предел сканирования
   `64 KiB`.
7. Перенести регрессионные тесты конфигурации и TUI, затем проверить
   сгенерированную схему и snapshot-представление нескольких больших файлов.

## Проверки

Тесты конфигурации подтверждают эффективное значение по умолчанию, явное значение
и отказ от нуля. TUI-тесты должны отличать контракт на каждый файл как от прежнего
общего бюджета, так и от текущего неограниченного upstream-предпросмотра:
несколько файлов получают собственное содержимое, каждый ограничивается отдельно,
а `transcript` сохраняет полный diff.

Данные запусков уровня карточки для `fork tests`:

```json
{
  "schema": "fork-tests.v1",
  "tests": [
    {
      "purpose": "значение по умолчанию, переопределение и положительный бюджет diff-preview",
      "argv": ["just", "test", "-p", "codex-core", "tui_diff_preview_max_rows_per_file"]
    },
    {
      "purpose": "отдельный бюджет строк каждого файла и полный diff в transcript",
      "argv": ["just", "test", "-p", "codex-tui", "patch_preview_"]
    }
  ]
}
```

Изменение конфигурационного контракта требует актуальной сгенерированной схемы.
Изменение видимого TUI-представления требует inline snapshot coverage в тестах
уровня карточки.

## Риски и ограничения

- Общего ограничения строк содержимого больше нет. Для `N` крупных файлов
  основной предпросмотр может содержать до `300 × N` строк при конфигурации по
  умолчанию; это осознанный компромисс в пользу наблюдаемости каждого изменённого
  файла.
- Пользователь может задать значительно большее положительное значение и вернуть
  дорогую отрисовку больших diff. Защитное ограничение сканирования сдерживает
  отдельные патологические входы, но не ограничивает суммарную высоту множества
  файлов.
- Число видимых исходных строк зависит от ширины терминала, Unicode width и
  переносов, поскольку бюджет определён в отрисованных строках.
- Единственный итоговый маркер сообщает, что сокращён хотя бы один файл, но не
  помечает сокращённые файлы по отдельности.
- Полный `transcript` намеренно не ограничивается новой настройкой и может
  оставаться дорогим для очень больших diff.
