# FU-2026-004: адаптивные разделители строк в TUI Markdown-таблицах

## Кратко

| Поле | Значение |
| --- | --- |
| Статус | `accepted` |
| Суть | Добавить адаптивные разделители строк тела таблицы для длинных Markdown-таблиц с переносами в TUI renderer. |
| Почему важно | Короткие таблицы должны оставаться компактными, но многострочные строки без разделителей плохо читаются. |
| Когда вернуться | После рефакторинга документации, когда будет понятно, какие таблицы реально остаются и как они рендерятся с переносами. |
| Когда закрыть | Если длинные ячейки с переносами исчезнут, будет выбран внешний renderer или тест покажет, что разделители не помогают. |
| Следующий шаг | Оценить реальные таблицы, затем добавить regression tests для compact и wrapped режимов. |
| Связи | [code:markdown-render], [code:markdown-render-tests], [test:long-link-table-rendering], [follow-up:FU-2026-003] |

## Наблюдение

Codex TUI сейчас рисует Markdown-таблицы Unicode box-таблицей с верхней
границей, разделителем заголовка и нижней границей. Между строками тела таблицы
горизонтальных разделителей нет. Для коротких таблиц это компактно и хорошо,
но длинные ячейки с большим количеством ссылок переносятся на несколько
визуальных строк, и становится трудно увидеть границу между логическими
строками таблицы.

## Почему это важно

При рефакторинге документации мы хотим оставлять таблицы там, где они остаются
обзорными, и не терять ссылки или контекст ради line-length lint. Тестовый
документ `docs/table-rendering-long-links-test.md` показал, что широкие таблицы
могут быть приемлемы по ширине, но для строк с переносами нужны визуальные разделители
между логическими строками.

## Что нужно сделать

- После рефакторинга документации оценить реальные таблицы, которые остаются в
  `docs/`.
- Спроектировать адаптивный режим: не добавлять разделители строк тела для мелких
  таблиц, но включать их, если хотя бы одна ячейка тела переносится на несколько
  отрендеренных строк или превышает выбранный порог длины.
- Не делать простой separator, включенный всегда, чтобы короткие таблицы не стали
  визуально тяжелее.
- Добавить regression tests в `codex-rs/tui/src/markdown_render_tests.rs`:
  короткая таблица остается compact, длинная/wrapped таблица получает
  горизонтальные разделители между строками тела таблицы.
- Проверить, что fallback pipe rendering для слишком узкого терминала не ломается.

## Когда вернуться

После согласования и выполнения рефакторинга документации, когда будет понятно,
какие таблицы реально остаются и какие из них рендерятся в терминале как
многострочные.

## Когда закрыть как неактуальное

Если документационные таблицы перестанут иметь длинные ячейки с переносами, если
будет выбран внешний терминальный Markdown renderer с подходящим стилем таблиц, или
если test rendering таблиц покажет, что разделители не улучшают читаемость.
